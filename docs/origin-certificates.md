# Origin certificates for the WordPress droplets

`tf/infra/singletons/cloudflare_origin_ca.tf` issues one Cloudflare Origin CA certificate (15 years) for `gpo.ca`, `*.gpo.ca`, and `*.secure.gpo.ca`. The private key is generated by the `tls` provider and stored in the singletons state.

Origin CA certificates are trusted only by Cloudflare, so serve this one only on **proxied** hostnames. DNS-only hostnames such as `staging.secure.gpo.ca` keep a publicly trusted certificate.

## Installing on a droplet

```bash
scripts/install-origin-cert.sh forge@<host>
```

The script reads the certificate and key from `tofu output`, writes `/home/forge/ssl/origin/cert.pem` and `key.pem` (0600) as `forge`, and reloads nginx when `service nginx configtest` passes. Re-running it changes nothing unless the certificate changed.

Each vhost that should serve the certificate needs a one-time root edit pointing `ssl_certificate` and `ssl_certificate_key` at those files, in both the site file and its `forge-conf/<site>/before/redirect.conf`. Forge rewrites those lines if its SSL settings are changed for the site, so manage the site's TLS here, not in Forge.

| Droplet | Vhosts on the Origin CA certificate | Vhosts that keep a public certificate |
|---|---|---|
| `staging` | `staging.gpo.ca` | `staging.secure.gpo.ca` (DNS-only) |
| `prod1` | `gpo.ca`, `secure.gpo.ca` | none |

## Renewal

Expires 15 years after issue. Replace by tainting `cloudflare_origin_ca_certificate.gpo_ca_origin` (and `tls_private_key.gpo_ca_origin` to rotate the key), applying, and re-running the install script on each droplet.
